## Warnings

### WR-02: `resolvedPath()` resolves a relative path against the current directory, so `isBelow()` and `samePath()` now accept it where the old code refused

**File:** `src/app/mac_check/main.cpp:193-210`
**Issue:** A relative path such as `home` or `build/x/home` is passed to `QFileInfo(head).canonicalFilePath()`, which resolves it against the current working directory. The old code compared the cleaned relative string with an absolute root and always refused. The new code accepts it whenever the working directory happens to make it resolve below the root or equal to `<out>/home`. The reachable inputs are HOME, CFFIXED_USER_HOME, `QDir::homePath()` and the paths returned by Cocoa and by the panels. A relative HOME is unusual. The point of `homeRedirected()` is that the two panel sections must never reach the user's folders, and its safe direction is refusal. The accepted path still depends on the working directory, which a later `chdir` could change. The old code did not have this dependence.
**Fix:** Treat a path that is not absolute as unresolvable, so both predicates refuse it:
```cpp
QString resolvedPath(const QString& path) {
  const QString cleaned = QDir::cleanPath(path);
  if (!QDir::isAbsolutePath(cleaned)) {
    return QString();  // empty and relative paths never match anything
  }
  ...
}
```
Then update the comment above the function ("An empty path stays empty") to say that a relative path does too.

## Info

### IN-05: `resolvedPath()` is weaker than the harness guard it is documented to match (cleans before it resolves; a dangling symlink counts as missing)

**File:** `src/app/mac_check/main.cpp:190-210`
**Issue:** The comment says the function gives the symlink-resolved form for comparison with the guard's output. Two cases differ from `harness::outputDirIsStrictlyInside()` in `HarnessGuards.h`. Neither is new, because the old lexical check accepted both as well.
1. `QDir::cleanPath()` runs first and collapses `..` lexically. `<out>/home/link/..` becomes `<out>/home`, although the operating system resolves it to the parent of the link target. The guard keeps `..` until it has examined it for this reason.
2. For a dangling symlink, `canonicalFilePath()` returns an empty string, so the function treats the link as a name that does not exist yet. It climbs past it and re-appends the link name below its canonical parent. The guard counts a dangling link as existing, so it refuses it.

The result can be "below root" for a path whose real target lies outside it.
**Fix:** Either refuse a path that still contains a `..` component after absolutising, or use `QFileInfo::exists() || isSymLink()` to decide where the existing part ends, as the guard does. Alternatively, narrow the comment so it does not claim the guard's strength.

### IN-06: `testHarnessMainsUseTheGuard`: the control cannot fail on a harness change, and the `return 2;` window can pass for an inverted guard

**File:** `src/qt_tests/tst_mac_qt.cpp:2108-2125`
**Issue:**
- The control (line 2110) calls `QString::contains` on a literal that it has itself just written. It can fail only if someone edits that literal or `oldCheck`. It does not exercise the file search (`readUtf8` and `contains` on the real text). The positive `call >= 0` check on the real files already covers that.
- The new window takes five lines from the first occurrence of `harness::outputDirIsStrictlyInside(` and looks for `return 2;`. It does not require the negation. A harness that wrote `if (harness::outputDirIsStrictlyInside(...)) { ...; return 2; }` passes, as does a check whose result is ignored when the `return 2;` of the next `mkpath` failure falls inside the window. A reformat that adds lines between the call and the return also fails it falsely.

All three mains pass today (the call is one line, and the `return 2;` is two lines below it).
**Fix:** Anchor the negation in the search string and drop the vacuous control, for example:
```cpp
const QString guardCall = QStringLiteral("if (!harness::outputDirIsStrictlyInside(");
```
Keep the five-line window for `return 2;`.
