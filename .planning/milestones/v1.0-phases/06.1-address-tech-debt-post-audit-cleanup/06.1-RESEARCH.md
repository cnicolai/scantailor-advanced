## Summary

The phase is about 40 small to medium closures plus three build-file changes, one new read ceiling, one UBSan clean-up and one measurement. Nothing in it needs a new library. The current tree confirms the CONTEXT's reading: of the 8 + 13 + 9 + 8 + 8 + 13 = 59 recorded findings, 33 are `open` and 8 are `deferred` (7 in Phase 2, 1 in Phase 3). Four are already moot after Phases 3 to 6 (Phase 1 IN-01, the `PORTABLE_VERSION` half of Phase 1 IN-02, Phase 2 IN-07, Phase 3 WR-01), the Phase 3 IN-03 UNC branch is provably unreachable, and a further handful need only a comment or an include change.

Four research results change the plans compared with the CONTEXT's assumptions. (1) **`Boost_INCLUDE_DIRS` is not empty under CMP0167 NEW with Homebrew Boost 1.92**: the config package sets it, so WR-04 is hygiene, not a live bug, and D-07's real effect on commands is that 297 of 473 compile lines change `-I/opt/homebrew/include` into `-isystem /opt/homebrew/include`. (2) **D-10 needs no compile-flag change**: `halt_on_error=1` in both `ASAN_OPTIONS` and `UBSAN_OPTIONS` makes an Apple Clang ASan+UBSan binary abort with exit 134 on the first report, passing test or not, while the unchanged `-fsanitize-recover=address` build keeps the collect preset working; this was probed. (3) **The `EstimateBackground.cpp:243` shift is a sign bug, but the corrected expression yields bit-identical results** on arm64 at `-O0` and `-O3` for widths 1 to 20000 (probed), so the fix is golden-safe; the same `<< 1` pattern occurs at ten sites in `Despeckle.cpp`, only four of which the tests reach. (4) **`gate.sh` has no reference for the current HEAD input state** (the last Phase 6 commit was not gated), so the first plan must run `gate.sh snapshot`.

**Primary recommendation:** Plan the phase as about 16 small, individually gated plans in this order: bookkeeping and docs, the small code and test fixes, D-11, D-08, the D-05 comment batches (5 batches of 4 to 10 files each), the UBSan fixes and the strict preset, D-06, D-07, the D-13 measurement, and a closing plan that runs the full strict ASan suite once, updates the six disposition files and runs the closing greps.

## Architecture Patterns

### Per-commit gate and the plan shape it implies

```
plan task -> edit -> xcrun clang-format -> git commit
          -> bash .planning/phases/03-qt-6-and-macos-only/gate.sh check <label>
               (configure + build + ctest macos-release, macos-debug; goldens vs a796c2ae;
                sorted `ninja -t commands` of 8 test/app targets + ui_snapshot vs HEAD~1 reference)
          -> one row in .planning/phases/06.1-.../records/gate-log.md
```

Facts about `gate.sh` that the plans must respect [VERIFIED: `gate.sh` read in full this session]:

- It must run from the repository root, refuses a set `UPDATE_GOLDENS`, and refuses to run if `src CMakeLists.txt CMakePresets.json cmake config.h.in version.h.in` have uncommitted changes. Commit first, then gate.
- `snapshot` writes the build-command reference of the committed HEAD into `build/scratch/gate/ref/cmds-<preset>-<key>.txt`, where `key` is a hash of `git ls-tree -r <commit> -- <INPUTS>`. `check <label>` compares the commands of HEAD with the reference of `HEAD~1` and, after the run, writes the reference of HEAD, so consecutive gated commits chain.
- **There is no reference for the current HEAD input key** (key `70fa7c4a...`; no file with that key in `build/scratch/gate/ref/`, 146 files). Commits `5bf8fe1e` (WR-07) and its predecessors under `src/` were the last gated state of Phase 6 only in part (the Phase 6 gate-log row `r06-review-fix` says "not measured"). **The first plan must run `bash .planning/phases/03-qt-6-and-macos-only/gate.sh snapshot` on the clean HEAD.** Without it the first `check` prints "no reference for HEAD~1" and FAILs.
- A commit that changes none of the INPUTS (only `.planning/`, `.claude/`, `.gitignore`, `TESTING.md`, `README.md`) has the same key as its parent; no gate run is needed for it. Anything under `src/` or any CMake file is an INPUT.
- Pass/fail does not depend on the size of the command diff. An intentional command change (D-06, D-07, new test source, `CMAKE_OSX_ARCHITECTURES`) passes as long as build, ctest and goldens pass; the gate-log row then has to explain every diff line (Phase 6 rows `s14`, `s18` to `s22` are the model: "token comparison: only these tokens left or entered").
- The compared targets are `scantailor-advanced pipeline_tests core_tests qt_tests dewarping_tests imageproc_tests math_tests foundation_tests` plus `ui_snapshot` when it exists. `retina_check`, `mac_check` and the `macos-asan` tree are **not** in the diff; the build of the whole default target set still happens in `cmake --build --preset`.
- A comment-only commit must show `diff_lines=0` for both presets. For D-05 any non-zero diff is a sign of an accidental code or CMake change.
- Cost: configure + build + ctest of Release (about 67 s test time) and Debug (about 247 s test time) per gate; budget 6 to 10 minutes per gated commit, more after a CMake change (full rebuild).
- Gate-log home for this phase: `.planning/phases/06.1-address-tech-debt-post-audit-cleanup/records/gate-log.md`, same columns as `.planning/phases/06-hardening-and-cleanup/records/gate-log.md` (Label, Commit, Subject, Release ctest, Debug ctest, Goldens, Command diff, Expected diff met).

### Disposition-file mechanics
The six `NN-REVIEW-DISPOSITION.md` files carry the state twice: the YAML frontmatter (`findings[].disposition`, `open:`, `total:`) and the table `| Finding | Severity | Disposition | Source |`. Allowed disposition values are `open`, `fixed`, `skipped`, `deferred` (footer of each file). "Won't-fix" has no keyword of its own: use `skipped` for won't-fix and `deferred` for deferred, each with a one-line reason in the Source cell. Edit the frontmatter, the table and the `open:` count together. Phase 2's table has 13 rows (the ids IN-01 to IN-04 were reused by the re-review; see the Phase 2 note below).

### Anti-Patterns to Avoid
- **Gating a commit that edits the input files while the tree is dirty:** the gate refuses; commit first.
- **Skipping the gate for a src-touching commit:** the next `check` has no reference and fails (this happened to `r06-review-fix`).
- **Letting D-05, D-06 and D-13 each touch `CMakeLists.txt:37-43` in separate plans:** merge conflicts and three gate rows for one block. Make one plan own that block (see below).
- **Using `UPDATE_GOLDENS` to make a UBSan fix pass:** forbidden by D-00a and D-10; the fallback is a narrow suppression plus a backlog entry.

## Don't Hand-Roll

| Problem | Don't build | Use instead | Why |
|---------|-------------|-------------|-----|
| Making the sanitizer preset fail on findings | A log scanner or per-test `FAIL_REGULAR_EXPRESSION` | `halt_on_error=1` in `ASAN_OPTIONS` and `UBSAN_OPTIONS` of the test preset | Verified: aborts with exit 134 on the first report; catches passing tests |
| Boost include path | `include_directories(${Boost_INCLUDE_DIRS})` | `link_libraries(Boost::headers)` | Imported target carries the include dir and is the documented config-mode interface |
| Canonical "strictly below build/" check | Another `QDir::cleanPath` compare | `QFileInfo::canonicalFilePath()` / `QDir::canonicalPath()` on the existing ancestor, then `startsWith(root + "/")` and `!= root` | Resolves symlinks; the lexical compare is exactly the finding |
| Forged-header test input | A hand-written TIFF byte string | `test_support::forgedTiff({{w, h, bits, samples, false}})` (`src/test_support/ForgedImages.h`) | Already used by `TestImageSizeLimit.cpp`; footprint sampler `test_support::FootprintSampler` in `ProcessMemory.h` |
| Token comparison of command diffs | `sed` normalisation | A short `python3 -I` script over the two `cmds-*.txt` files comparing token multisets per line | Phase 6 record `s14` notes that sed normalisation could not pass; token comparison is the accepted form |

**Key insight:** every item that looks like new infrastructure already exists in `src/test_support/`, `gate.sh` or the preset mechanism; the phase adds constants, call-site edits and one shared header.

## Common Pitfalls

### Pitfall 1: gating without a reference
**What goes wrong:** the first `gate.sh check` prints "no reference for HEAD~1; run snapshot on the parent first" and FAILs, as `r06-review-fix` did.
**Why it happens:** the ref file name embeds a hash of the INPUTS tree; the current HEAD state has none.
**How to avoid:** first task of the first plan: `bash .planning/phases/03-qt-6-and-macos-only/gate.sh snapshot` on the clean tree; gate every src or CMake commit in order.
**Warning signs:** `result: FAIL` with `cmds-*: diff_lines=1`.

### Pitfall 2: the strict preset red in the middle of the phase
**What goes wrong:** flipping `halt_on_error=1` before the UBSan fixes makes `ctest --preset macos-asan` red in four of seven suites.
**How to avoid:** land the fixes first (or in the same plan), verify with the three fast asan binaries and the single pipeline case, then run the full strict suite once at the end. A stale `build/macos-asan` (built before WR-07) needs an incremental rebuild first.

### Pitfall 3: `__LINE__` and comment edits
**What goes wrong:** D-05 shifts line numbers; any test that pins a line number breaks.
**How to avoid:** none expected (`git grep` for `__LINE__` assertions is cheap to confirm), the gate's unchanged goldens and a 0-line command diff are the proof. The `mac_check` literal at `main.cpp:597` is output text of an unrun harness; changing it is harmless.

### Pitfall 4: checking a symlink guard after `mkpath`
**What goes wrong:** the finding's own fix text calls `canonicalFilePath()` "after `mkpath`", which already created directories through the link.
**How to avoid:** resolve the deepest existing ancestor first; create only after the check. Test it by asserting the link target stayed empty.

### Pitfall 5: ugrep versus git grep
**What goes wrong:** the shell `grep` is ugrep; `\b`, `\|` and `$` behave differently, and an empty result can mean a bad pattern.
**How to avoid:** use `git grep -n -P` for the closing checks and give each a positive control (the same command with a pattern known to hit, or run on a copy that still has a hit). Verified this session: `git grep -n -E` with `\b` returned nothing (BSD regex), `git grep -n -P` returned 93.

### Pitfall 6: D-05 and D-08/D-06 touching the same lines
**What goes wrong:** batch B edits `ui_snapshot`, `retina_check`, `mac_check` mains that D-08 also edits; the top-level `CMakeLists.txt:38,41` is edited by D-05, D-06 (WR-02) and D-13.
**How to avoid:** order D-08 before batch B; give `CMakeLists.txt:37-43` to the D-06 plan only.

### Pitfall 7: include pruning removes a transitive dependency that other TUs need
**What goes wrong:** a greedy "remove include if the file still compiles" pass can delete an include whose symbols arrive through a header that later changes.
**How to avoid:** syntax-only compile of the one TU per candidate, then a full gate (all targets build, 7/7 tests, goldens). For headers (`OutputGeneratorProcessor.h`, `OutputGeneratorPixelOps.h`) a removal must be checked against every including `.cpp`, so prune the `.cpp` files first and the headers last, and re-run the full build. Keep includes that declare a type named in the file even if transitively available when the executor judges the file would otherwise lose self-description.

### Pitfall 8: `Boost::headers` global link
**What goes wrong:** `link_libraries(Boost::headers)` placed after `add_subdirectory(src)` has no effect.
**How to avoid:** put it in the Boost block (line ~97), which precedes `add_subdirectory(src)`; confirm 0 remaining `-I/opt/homebrew/include` tokens in `ninja -t commands` output.

```cpp
  const int height = size.height();
  if (width < 0 || height < 0) {
    return true;  // a header value of 2^31 or more
  }
  return width > kMaxOwnFileSide || height > kMaxOwnFileSide || qint64(width) * height > kMaxOwnFilePixels;
}
```
