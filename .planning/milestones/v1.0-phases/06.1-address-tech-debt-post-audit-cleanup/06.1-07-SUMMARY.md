# Phase 06.1 Plan 07: Harness output guard and empty batch Summary

The three harnesses now share one canonical output-directory guard (symlinks of the existing part resolved, no `..` in the new part, strict descendant of `build/`, nothing created before the check), `ui_snapshot` rejects unknown options, and an empty batch returns before it reads the queue it just reset.

## Accomplishments

- Shared guard (D-08, tracer): `src/app/HarnessGuards.h` holds `harness::outputDirIsStrictlyInside(outArg, root, &resolved, &error)`. It canonicalises the root, makes the argument absolute without cleaning, walks up to the deepest existing ancestor (a dangling symlink counts as existing, so it is refused), refuses `..` in the tail, resolves the ancestor with `canonicalFilePath()` and accepts only a result below `canonicalRoot + "/"`. Three `TestMacQt` cases call it directly under a fake root in `TEST_TMP_ROOT`: a new directory inside (accepted, `sub` not created), the root, `root/../x`, `root/sub/../../x`, an empty argument and the prefix sibling `rootX` (refused, the output parameter untouched), and a symlink to a sibling folder or a dangling symlink (refused, the link target stays empty and nothing appears at the dangling target).
- Mutation proof: with the existing part not resolved (`canonicalBase = base`), `testHarnessGuardRefusesSymlinkOut` failed on the first symlink case; restored by hand (the header was still untracked) and rebuilt.
- Real offscreen runs of `ui_snapshot`: `ui_snapshot build/scratch/ui-snap-t07` exit 0 (main-window.png, settings-dialog.png, texts.txt, settings and tmp below it); `ui_snapshot build` exit 2 with `is not strictly inside` and no `build/tmp`, no `build/settings`; `ui_snapshot --bogus build/scratch/ui-snap-t07b` exit 2 with `unknown option --bogus` and no directory; `ui_snapshot build/scratch/ui-snap-t07c --assert-no-language` exit 0.
- Harnesses (D-08): `retina_check` and `mac_check` replace the lexical `out.startsWith(root + "/")` check by the shared guard, before any `mkpath` and before `retina_check`'s recursive removal of its thumbnail folder. `ui_snapshot` builds a `QStringList` from `argv` and calls `harness::parseSnapshotArgs`, which allow-lists `--assert-no-language`, refuses every other `-` argument naming it, and counts positional arguments instead of doubling a flag. `testSnapshotArgsRejectUnknownOptions` covers the accepted forms and four refusals; `testHarnessMainsUseTheGuard` scans the three mains for the guard call and the absence of the old literal (a control line proves the search finds it) and `ui_snapshot` for the parser call. `retina_check` and `mac_check` were built in both presets by the gate and never run (D-00b).
- Empty batch (D-14): `startBatchProcessing()` now has `return;` after `stopBatchProcessing();` in the `else` branch, with one comment line. `testEmptyBatchStopsCleanly` opens a one-page project, removes the only page through the thumbnail context menu (`RemovePageAnswerer` activates "Remove from project ..." in the popup and accepts the confirmation dialog), then starts a batch and checks the filter list is enabled and the window alive. Red run before the fix: `qt_tests` crashed with SIGSEGV at address 0x28; green after.
- Gates: `t07-guard-snapshot` (`db8e618b`), `t07-guard-harnesses` (`acc893f0`), `t07-empty-batch` (`73b538a5`) all PASS, Release and Debug `100% tests passed out of 7`, goldens unchanged, command diffs empty (0 / 0).
