## Facts at planning time (HEAD f6cc4457)

- Dialogs: `openSettingsDialog()` (MainWindow.cpp:1517), `openDefaultParamsDialog()` (1525), `showAboutDialog()` (1557) and `showRelinkingDialog()` (875) create window-modal dialogs and `show()` them; `fixDpiDialogRequested()` (1366) and `showRelinkingDialog()` return early without a project, so the harness constructs `FixDpiDialog(std::vector<ImageFileInfo>(), &window)` and `RelinkingDialog(projectFilePath, &window)` itself and shows them window-modal. `DefaultParamsDialog` owns a `DefaultParamsProfileManager`, whose default constructor uses `QStandardPaths::writableLocation(QStandardPaths::AppDataLocation) + "/profiles"` (`src/core/DefaultParamsProfileManager.cpp:19`) and lists that folder: without a redirected home this is `~/Library/Application Support/...`, which the harness must not touch.
- Panels: `RelinkingDialog::pathButtonClicked(const QString& prefixPath, const QString& suffixPath, int type)` is a private slot (callable by name) that opens `getOpenFileName` for `RelinkablePath::File` and `getExistingDirectory` for `RelinkablePath::Dir`, starting in the prefix's folder if it exists, else the project file's folder; `MainWindow::openProject()` (private slot, 1465) starts in `QSettings` key `project/lastDir`; `ProjectFilesDialog::inpDirBrowse()` starts in the input line edit or `QSettings` key `lastInputDir`, else `QDir::home()`; `outDirBrowse()` starts in `outDirLine`'s text, else `QDir::home()` (`ProjectFilesDialog.cpp:236-262`). `MainWindow.cpp:1427` (Save Project As), `OutOfMemoryDialog.cpp:62` and `MainWindow.cpp:1862` (Files to insert) need a loaded project and are covered by `testNoDontUseNativeDialog` (plan 05-09).
- A native `QFileDialog` on Cocoa runs an application-modal NSOpenPanel or NSSavePanel; `[NSApp modalWindow]` is the panel; `cocoaprobe::runLater` (plan 05-02) runs in the modal-panel run-loop mode, so a block scheduled before the panel opens can inspect and cancel it.
- The static `QFileDialog::getOpenFileName` and `getExistingDirectory` build a `QFileDialog` object with the given parent and return the selection only when its `exec()` ends `QDialog::Accepted`, else an empty string; while the native panel is up that object is Qt's modal widget (the same object step 4's 3000 ms fallback closes). Its `finished(int)` signal carries the result and `filesSelected(const QStringList&)` fires only on accept, so the harness can observe the path a cancelled call returns without touching the production slot. If the object is not found, the row records `unobserved` and the verdict fails, so this assumption checks itself.
- Relinking substitution: `RelinkingDialog::relinker()` (`src/app/RelinkingDialog.h:38`) returns the model's `AbstractRelinker`; `AbstractRelinker::substitutionPathFor(const RelinkablePath&)` (`src/core/AbstractRelinker.h:19`) returns the original normalized path when no mapping exists. `pathButtonClicked` returns early on an empty path (`RelinkingDialog.cpp:82` at HEAD) and otherwise changes only the model's uncommitted paths (`RelinkingModel::replacePrefix`); the relinker sees a change only after `RelinkingModel::commitChanges` (`RelinkingModel.cpp:210-243`), which the dialog's private slot `commitChanges` (the OK button's slot, `RelinkingDialog.cpp:115`) calls before `accept()`. Comparing `relinker()->substitutionPathFor(orig)` without that commit would hold whatever the panel returned.
- Unbundled AppKit processes keep NSUserDefaults (including file-panel state) in a preferences domain under the home directory. `CFFIXED_USER_HOME` and `HOME` set at launch redirect CoreFoundation's and Qt's home; the harness checks the result instead of trusting it.
- Qt keeps the previous menu bar when the focus window has no bar and no parentless bar exists; with a parentless bar, dialogs get that bar instead (RESEARCH Pitfall 6, `qcocoamenubar.mm`). `QCocoaMenuBar` may leave items enabled under a window-modal dialog (assumption A9).

## Reconciliations

- UI-SPEC section 1 (step 2) and E6 describe the fallback as a parentless bar with File (`actionQuit`) and Help (`actionAbout`). RESEARCH Pitfall 6 shows that such a bar would replace the full bar during every dialog and shrink it. This plan keeps the decision's intent (measure first, add a fallback only if the bar is empty or reduced, never duplicate About or Quit) and, if a fallback is needed, gives it the same menus as the main bar, built from the same `QAction` objects.
- VALIDATION and UI-SPEC name "Default Parameters" among the measured dialogs; it runs here only with a redirected home (its profile folder would otherwise be under `~/Library`).
