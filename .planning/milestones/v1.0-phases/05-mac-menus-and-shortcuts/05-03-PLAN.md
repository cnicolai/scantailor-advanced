## Reconciliations

- UI-SPEC: the View zoom actions use "the same focus rule as the plain keys (cursor if it is over the view, else the view centre)". RESEARCH Pattern 4 notes that ZoomHandler's own cursor focus reads an internal position that is (0, 0) until the first mouse move. This plan implements the UI-SPEC rule literally from `QCursor::pos()`: the cursor when it lies inside the view, else the view centre. Like `ZoomHandler::zoom`, it does nothing while the view's interaction is captured; unlike it, zooming out at 1.0 does not nudge the view (RESEARCH: the menu path needs neither).
- D-03 vs UI-SPEC E3: orchestrator decision 2026-11-14. The six stage actions stay disabled when no project is loaded, as the UI-SPEC "Empty state" row and row E3 specify (the user approved the UI-SPEC). D-03 governs the key bindings O, E, N, V, K and P, and those stay unchanged: each stays bound to its stage action (`actionSwitchFilter1..6`, letter as the second sequence after the ⌘ digit). With no project there is no stage to switch to, so disabling the actions in that state changes nothing the user relies on; with a project loaded the letters work exactly as today. This is a decision on D-03's scope, not a change to it, and the executor implements it as written in Task 1 step 3.
