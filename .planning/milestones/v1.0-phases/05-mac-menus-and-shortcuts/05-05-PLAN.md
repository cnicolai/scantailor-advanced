## Facts at planning time (HEAD f6cc4457) and from earlier plans

- `mac_check` (plan 05-02) has `Summary`, `waitFor`, `--section` lists, the activation sequence of `runMenubarSection` and the `cocoaprobe` API (`keyCodeFor`, `sendKey`, `sendMouse`, `mainMenu`, `activate`, `runLater`); `records/layout.md` names the chord groups bound by plan 05-03.
- Production connections that must not run while keys are counted: `actionNewProject` opens the new-project dialog, `actionOpenProject` a native panel, `actionSaveProjectAs` a save panel, `actionQuit` closes the window, `actionSettings` the Settings dialog (string-based connections to the window, `MainWindow.cpp:320-328`); the thumbnail actions are lambdas connected without a context object, whose receiver is the action itself (`MainWindow.cpp:258-263`). Disconnect with `QObject::disconnect(action, &QAction::triggered, &window, nullptr)` and `QObject::disconnect(action, &QAction::triggered, action, nullptr)`; the zoom actions stay connected because their effect is measured.
- The Quit item of the application menu may reach the app either as the `QuitRole` action or as an application termination request that Qt turns into close events (RESEARCH could not settle which); an event filter on the window that counts and swallows `QEvent::Close` makes either route observable without closing the window.
