Conventions: as in plan 02-01, section "Conventions for every plan of this phase".

Freezing rule (D-12, fixed here). Measurement: build `macos-release` and `macos-debug`, run each binary's full `pipeline_tests --log_level=message`, and take every `GOLDEN-METRIC` line (format from plan 02-02). Release compares against goldens recorded from Release, so its spread is expected to be 0; Debug against the same goldens gives the Release/Debug spread. Per image kind and metric, take the maximum value over both runs. Step grid and ceiling per metric: `edge_tolerant_xor_fraction` step 0.0001, ceiling 0.001; `component_count_relative` step 0.001, ceiling 0.02; `mae` step 0.05, ceiling 0.5; `max_abs_error` step 1, ceiling 8; `shift` fixed at 0 (not tunable). Frozen limit = the smallest grid value strictly greater than the measured maximum, capped at the ceiling. If a measured maximum already reaches its ceiling, freeze nothing for that metric and stop with a report: the Release and Debug builds then differ more than the user's ceilings allow, which is a decision for the user. Text-golden limits stay at the D-14 values (0.01°, 1 px, 0.05 mm, exact otherwise); record their measured spread to show it lies below them. Research measured a spread of 0 on its spike fixtures, so frozen values of 0.0001, 0.001, 0.05 and 1 are the expected outcome.
