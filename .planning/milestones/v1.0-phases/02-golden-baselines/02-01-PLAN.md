## Decisions taken at planning time (Claude's discretion, recorded here)

- Code layout: `src/test_support/` is a static library that links only `Qt::Gui` and `Qt::Core` (plan 02-02 adds the image libraries for the manifest); it never links `core`, so `imageproc_tests` and `dewarping_tests` can use it. `src/pipeline_tests/` is a Boost.Test executable that links `core` and `test_support`. Both new directories collect their sources with `file(GLOB ... CONFIGURE_DEPENDS)` so that parallel plans add test files without editing a shared list; production CMake keeps its explicit lists.
- PRNG: own splitmix64 with an explicit `% n` (research Pattern 1). Glyphs: a 5x7 bitmap table written as ASCII-art strings. Trigonometry: hand-written Taylor series for the small angles used (|angle| ≤ 0.1 rad); never libm `sin`/`cos`.
- Fixture storage: inputs are generated in memory on every run, never committed; plans 02-05 to 02-07 commit SHA-256 fingerprints of them per golden suite.
- Output DPI: set explicitly to 600 for every scenario, which is the app default (`src/core/DefaultParams.cpp:162`, `OutputParams() : m_dpi(600, 600)`), so 300 dpi inputs exercise upscaling and 600 dpi inputs the identity path. Every text golden records it (research Open Question 3).
- Test environment lives in `set_tests_properties(... ENVIRONMENT ...)` and is also set by the global fixture with `qputenv` before the application object exists, so direct runs of the binary (as the golden-recording steps of later plans use) behave like ctest runs. `CMakePresets.json` stays unchanged (research Open Question 4).
