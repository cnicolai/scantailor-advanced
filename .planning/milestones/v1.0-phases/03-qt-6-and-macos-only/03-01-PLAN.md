## Conventions for every plan of this phase

Later plans refer to this section; they repeat the items their tasks need.

1. Every command runs from the repository root; every path in a plan is relative to it.
2. Scratch files go to `build/scratch/` (gitignored), never `/tmp` or anywhere outside the project. Write files with the Write tool; never run a bare `cat > file` (it can block on stdin).
3. Nothing outside the project is opened, listed or written by you. In particular never touch `~/.config/scantailor-advanced/` or `~/Library/...` (D-07). Build tools and the programs built from this checkout may read `/opt/homebrew` and the Xcode / Command Line Tools installation (approved for Phases 3 to 6 in `.planning/phases/02-golden-baselines/records/access-approval.md`); do not open files there yourself.
4. Formatting: `clang-format` is not on PATH. Run `xcrun clang-format -i <file>` (repository `.clang-format`) on every C++ file you touch, except `src/dewarping/TextLineTracer.cpp`, which already violates the style at lines 317 and 328; `xcrun clang-format --dry-run src/dewarping/TextLineTracer.cpp` must keep printing exactly those two warnings.
5. Conditionals are resolved only with `unifdef -m`, naming only the symbols of the current category, never by hand. zsh does not word-split a variable, so feed file lists through `xargs`. `unifdef` exits 1 when it changed a file (`xargs` then reports 123): judge success by `git diff --numstat` (zero additions before formatting) and by the leftover search, never by the exit status. Read every resulting diff.
6. `grep` here is ugrep 7.8.4: use repeated `-e`, never `\|` inside `-E`, and no `-i` or `-w` in leftover searches of the source tree (RESEARCH Pitfall 4).
7. Gate (D-11). A strip commit is any commit of this phase that changes a path outside `.planning/` and `.claude/`. Every strip commit passes `bash .planning/phases/03-qt-6-and-macos-only/gate.sh check <label>` run on that commit. Commit first, then gate; when the gate fails, fix the cause, `git commit --amend`, and rerun with the same label until `result: PASS`. The gate takes 5 to 8 minutes: start it with the Bash tool in the background (`run_in_background`), wait for its exit notification (do not poll), then read `build/scratch/gate/<label>/summary.txt`. Never set `UPDATE_GOLDENS`.
8. After a strip commit passes, append its row to `records/gate-log.md` and commit that file alone as `docs(03-NN): gate record for <label>`.
9. Records: replace the repository path by `{repo}` and the home path by `~` before committing; `grep -c "$HOME" <record>` must print 0.

- Must run from the repository root: if `git rev-parse --show-toplevel` differs from `pwd -P`, print `gate: run from the repository root` and exit 2. If the variable UPDATE_GOLDENS is set at all (even empty), print `gate: UPDATE_GOLDENS is set; refusing (D-11)` and exit 2.

- Input key of a revision R: `git ls-tree -r R -- <inputs> | git hash-object --stdin`.
- Command list of preset P: `ninja -C build/P -t commands <targets>`, piped through `sed -E 's#CMakeFiles/d/[0-9a-f]{64}\.d#CMakeFiles/d/HASH.d#g'` and `LC_ALL=C sort`. `<targets>` is `scantailor-advanced pipeline_tests core_tests qt_tests dewarping_tests imageproc_tests math_tests foundation_tests`, plus `ui_snapshot` when `ninja -C build/P -t targets all` has a line starting with `ui_snapshot: `.
