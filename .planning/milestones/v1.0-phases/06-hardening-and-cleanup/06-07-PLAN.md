<objective>
SAFE-02. Phase 2 measured that `&`, `<`, `"`, NFC and NFD names already round-trip, and the research found that the only names QDom cannot write are those with XML-1.0-forbidden control characters (U+0001 to U+0008, U+000B, U+000C, U+000E to U+001F, U+FFFE, U+FFFF): QDom writes them raw and the project file no longer loads. The tracer adds an escape that is used only for such values and announced by a flag attribute, wires it into the three attribute sites of the project writer and reader, and proves end to end that a project with control characters in file, folder and output-folder names saves and reloads, while ordinary project files stay byte-identical. Then the D-10 matrix of unusual names is pinned, the backslash case is observed and handled per D-10, and the record is written.

## Decisions recorded by this plan (research open question 2)

- **Fix, not mark:** the flagged escape is implemented (research recommendation). It satisfies SAFE-02's wording ("survive saving and reloading") and keeps ordinary files byte-identical because nothing changes unless a value contains an XML-1.0-forbidden character. Fallback, only if the escape cannot keep ordinary files byte-identical: `XFAIL_CHECK` with a new backlog item 999.9 and `ProjectWriter::write` returning false for such names (the existing "Error saving the project file!" box) instead of writing an unloadable file; the SUMMARY then reports it to the user.
- **Escape format:** when `needsEscaping(value)` holds, the attribute value is `QString::fromLatin1(value.toUtf8().toPercentEncoding())` and a second attribute `<name>Escaped="1"` is written; the reader decodes with `QString::fromUtf8(QByteArray::fromPercentEncoding(text.toUtf8()))` only when that flag is exactly `1`. A literal `%01` in an unflagged ordinary name is never decoded.
- **Criterion 2 and the backslash:** criterion 2 asks that "the project round-trip test passes without expected failures" for names with `&`, `<`, `"` or non-ASCII. The backslash (D-10, backlog 999.8) is tested in its own suite `ProjectRoundTripBackslashTestSuite` in the same file, so `ProjectRoundTripTestSuite` itself never carries a mark.
- **Reversibility:** the flag attribute is new project-file surface. Only files that contain a forbidden character get it, and those files could not be loaded before, so an older build reading a new file sees percent-encoded text instead of a failure.
