The device-detail measure used below (same as the qt_tests helper `minBlockNonUniformFraction` of plan 04-04): over a region of interest of a device-pixel grab, for each of the four offsets (0 or 1 in x and y), the fraction of 2x2 blocks inside the region whose four pixels are not all equal within 2 levels per channel; the measure is the minimum over the offsets. A buffer rendered at ratio 1 and shown 2x with nearest sampling scores 0 at its aligned offset; a device-resolution rendering of edges or detail scores clearly above 0. A threshold that is missed is a FAIL: record it and report, never change the threshold.

Facts for the sections (read the named files for details):
- Thumbnails: `ThumbnailBase(std::shared_ptr<ThumbnailPixmapCache>, const QSizeF& maxSize, const ImageId&, const ImageTransformation&)`; `ThumbnailDprTracker(QAbstractScrollArea*)` and `setCache` (plan 04-04); the A4 page of `test_support::generatePage({FLAT, 300, 1, 0.0})` is 2480x3508, so at Quality 250 and ratio 2 the thumbnail is 354x500.
- Zone mask: the editor set-up of `testZoneMaskAtDeviceResolution` in `src/qt_tests/tst_hidpi_qt.cpp` (plan 04-05); diagnostics `screenPictureMask()`, `screenPictureMaskIsCurrent()`.
- Page badges: `ThumbnailSequence.cpp:1409-1423` takes `IconProvider::getIcon("left_page_thumb")` (or `right_page_thumb`, ...) and `pixmap(QSize(23, 17))` into a `QGraphicsPixmapItem`; the file is not changed in this phase (plan 04-06 pins it). The shipped `left_page_thumb.svg` (`viewBox="0 0 23 17"`) draws only lines and bars on whole logical pixels, so at ratio 2 its edges fall on even device pixels and a ratio-1 rendering upscaled 2x looks the same pixel for pixel. The live check therefore compares the grab with the pixmap drawn 1:1. The offscreen counterpart with a diagonal scratch badge, which rejects a ratio-1 badge, is `testPageBadgeAtDeviceResolution` (plan 04-06).
- Handles: `deskew::ImageView(const QImage& image, const QImage& downscaledImage, const ImageTransformation& xform)` draws four `aqua-sphere` handles (two on the rotation arc, two on the oblique arc) centred on `getImageRotationOrigin()`, the centre of the content area (deskew/ImageView.cpp:249-270), which is symmetric in the viewport; with the pre-phase bug every handle sat 8 logical pixels up and left of its anchor.
- Stage list: `StageListView` with a `StageSequence` as in `testStageAnimationFollowsScreenChange` (plan 04-05); the animation is drawn for the selected row once `setBatchProcessingInProgress(true)` runs (StageListView.cpp:159-210); diagnostic `batchAnimationFrames()`.
- Decorations: `RelinkingModel` returns `getIcon("file").pixmap(16, 16)` as model data (src/app/RelinkingModel.cpp:91-92); a `QStandardItemModel` item with that pixmap as `Qt::DecorationRole` in a `QListView` exercises the same item-view path without compiling app sources.
- Colour picker: `ColorPickupInteraction::medianColor(const QImage&)` (plan 04-06) and the patch set-up of `testColorPickerGrabAtRatio2`.
