<objective>
Fix the geometry of the small icon pixmaps and make the colour picker's sampling explicit for Retina. The icons are already sharp, because `QIcon::pixmap` returns ratio-2 pixmaps on this Mac, but the views centre and hit-test them by their device size, so on the Studio Display handles sit 8 logical pixels off, the trash icon 32 and the unremove button 64, with a hit area of 256 logical pixels. The page badges of the thumbnail list already have both the right resolution and the right geometry; a permanent offscreen test proves this on the real icon engine instead of taking it on trust. The colour picker keeps its semantics (median of the circle as drawn on screen) in a pure function that counts logical pixels, covered by tests at ratio 1 and 2.

Purpose: HIDPI-04 (handles, trash and unremove buttons, swatches, page badges; RESEARCH Pattern 6) and HIDPI-06 (success criterion 5, the sampling test that Phase 6 STRIP-07 relies on).
Output: five icon-site edits, `ColorPickupInteraction::medianColor`, four tests, two gated commits.
</objective>

Page badges need no code change, and Task 1 proves it by test (checker blocker HIDPI-04). Facts gathered at planning (HEAD 03083f55):
- `ThumbnailSequence::Impl::getLabelGroup` (src/app/ThumbnailSequence.cpp:1409-1433) takes `IconProvider::getInstance().getIcon("left_page_thumb")` or `"right_page_thumb"`, then `const QSize size = {23, 17};`, `pageThumb.pixmap(size)` and `pageThumb.pixmap(size, QIcon::Selected)`, puts each into a `QGraphicsPixmapItem`, and lays them out with `QRectF pixmapBox(pixmapItem->boundingRect());`. `IconProvider::getIcon` passes the call through to the pack.
- Both badge icons are `styled="on"` in `src/resources/icons.xml`, so they are `SvgStyledIconEngine` icons (`src/core/StyledIconPack.cpp:49-89`). That engine implements only `pixmap(size, ...)` and renders the SVG at exactly the size it is asked for. RESEARCH line 261 probed an engine of the same shape: in Qt 6.12, `QIcon::pixmap(QSize)` takes `qApp->devicePixelRatio()`, asks the engine for size times ratio and sets the ratio (16x16 gave 32 px at ratio 2). RESEARCH probe4 showed that `QGraphicsPixmapItem::boundingRect()` of a 46x34 ratio-2 pixmap is 23x17. Nothing in `src/` sets a graphics-item cache mode (`setCacheMode` has no hits), so the thumbnail view draws the item's pixmap directly.
- `qApp->devicePixelRatio()` is the maximum over the screens. On the Studio Display (the only display) and on `TwoX` that is the view's ratio. A 1x view next to a 2x screen gets a ratio-2 badge drawn at its 23x17 logical size, like the handle icons of Task 1. Building the badge at the view's own ratio would need a rebuild of every label group on a display change; without that rebuild, a list that starts on a 1x screen would keep ratio-1 badges on Retina, which is worse than today. So `ThumbnailSequence.cpp` stays as it is.
- The shipped badge art lies on the 1-logical-pixel grid, so a ratio-1 and a ratio-2 rendering of it look alike pixel for pixel. The test therefore uses a scratch styled icon with a diagonal edge, which tells the two apart.

Icon pack facts: `IconProvider::getIcon` returns a null `QIcon` when no pack is set (the normal state in qt_tests). `StyledIconPack(const QString& iconSheetPath)` reads an icon sheet like `src/resources/icons.xml` (`<icons><icon name="..."><file>path</file></icon>...</icons>`; `trashed` and `untrash` are not styled, so they are plain `QIcon`s from an SVG file). RESEARCH verified offscreen with the 2x screen present that `QIcon::pixmap(16, 16)` returns a 32-pixel pixmap with ratio 2 (`qApp->devicePixelRatio()` is the maximum over the screens). `InteractionHandler::paint(QPainter&, const InteractionState&)` and `proximityUpdate(const QPointF&, InteractionState&)` are public and dispatch to `UnremoveButton::onPaint` / `onProximityUpdate` (src/core/interaction/InteractionHandler.h:29-31); `onProximityUpdate` sets `redrawRequested` when the hover state changes from its initial `false`.

Colour picker facts: `ColorPickupInteraction::takeColor` (src/core/filters/output/ColorPickupInteraction.cpp:67-126) grabs `targetBoundingRect()` (15x15 logical around `mapFromGlobal(QCursor::pos())`, lines 128-133), converts to `Format_RGB32`, takes the pixels with `(x - xCenter)^2 + (y - yCenter)^2 <= xCenter * yCenter` (`xCenter = width / 2`) and the bit-mixing median through `bitMixColor` / `bitUnmixColor` and `nth_element` at `size() / 2`. RESEARCH verified offscreen that `grab(QRect(60, 30, 15, 15))` on a ratio-2 widget returns 30x30 pixels with ratio 2. With each logical pixel replicated d x d times, the median index `size / 2` of the replicated sorted list maps to the same element as at ratio 1, so the logical-pixel predicate keeps results identical for upscaled content.
