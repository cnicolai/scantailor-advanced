Each ends in a refusal. The guard creates nothing. `retina_check` already had the `src/app` include directory, and `qt_tests` gets it through the public include directory of `app_gui`.
- **`parseSnapshotArgs`:** it refuses any unknown `-` option, a missing output directory and a second positional argument.
- **Undefined-behaviour fixes:**
  - `Despeckle.cpp`, `InfluenceMap.cpp` and `SlicedHistogram.cpp` replace `<< 1` and `<< 5` by `* 2` and `* 32`. The results are identical for every input, including negative values.
  - `BinaryImage.cpp` uses `offsetof`. `SharedData` is standard-layout (no virtual members, one `QAtomicInt`, one array), so this is well-defined.
  - `EstimateBackground.cpp`: the old exponent `32 - width - 32 * idx` and the new `32 * (idx + 1) - width` agree modulo 32 for every width. The new one always lies in 0..31. Because the hardware masks the shift count to 5 bits, the old UB produced the same mask, so output equivalence holds.
- **`startBatchProcessing()` early return:** this is a real fix. Before it, `m_batchQueue->selectedPage()` ran on the pointer that `stopBatchProcessing()` had just reset.
- **Own-file ceiling plumbing:** `TiffReader`, `ImageLoader`, `Task.cpp` and `ThumbnailPixmapCache` pass the limit kind consistently, no `ImageLoader::load` caller remains, and the header check still runs before any allocation. The new forged-header tests cover the TIFF path and the pipeline path.

## Warnings

### WR-01: The own-file ceiling is below what the application can legitimately write, so the "every own file loads" guarantee does not hold

**File:** `src/core/ImageSizeLimit.h:46-55` (also `src/core/ImageLoader.h:16-20`, `src/core/filters/output/Task.cpp:258-296`)
**Issue:** The new comment justifies the ceiling of 2^30 - 1 px with "the largest plausible output is a 500 mm side at 1200 dpi" and states that every file the application wrote itself must load, because a refusal regenerates the page on every visit. Nothing limits the output dpi to 1200. `ChangeDpiDialog` accepts a custom value up to 9999 (`QIntValidator(0, 9999)`), and no write-side check compares the output size with `kMaxOwnFilePixels`. A bilevel output is cheap to write at high dpi: an A3 page (297 x 420 mm) at 2400 dpi is about 28063 x 39690 = 1.114 x 10^9 px, which is above 1073741823 px, while the TIFF stays near 140 MB. `loadOwnFile` refuses that file with a null image. `Task.cpp` then sets `needReprocess` and regenerates the page on every visit, which is the failure the comment says the ceiling prevents. Before this phase such a file loaded. The side limit (131070) is also exceeded at high dpi on tall pages, at A3 around 8000 dpi. The header comment "far above anything the application writes" in `ImageLoader.h` overstates the same assumption.
**Fix:** Either make the guarantee true or state its limit.
- Preferred: keep the constant, but document that outputs above the ceiling regenerate on every visit, and add a write-side bound. For example, have the output stage refuse (or warn about) a page whose output size would exceed `ImageSizeLimit::exceedsOwnFile`, so it cannot write a file it will later refuse.
- Minimum: reword both comments to say "an output larger than 2^30 px (for example A3 above about 2300 dpi) is refused and regenerated on every visit". If the user never uses such dpi values, record that as the accepted reason.

## Info

### IN-01: The control in `testHarnessMainsUseTheGuard` cannot fail

**File:** `src/qt_tests/tst_mac_qt.cpp:2108-2109`
**Issue:** The control is `QStringLiteral("if (out != root && !%1) {").arg(oldCheck).contains(oldCheck)`. The string is built from `oldCheck`, so it always contains `oldCheck`. The control proves nothing about the search, unlike the controls of the neighbouring scan tests, which feed a separate sample text. The test also only checks that the call text appears in each `main.cpp`. It does not check that the returned `out` is used or that a `false` result stops the harness.
**Fix:** Use a literal sample line copied from the removed code as the control, for example `QVERIFY(QStringLiteral("  if (out != root && !out.startsWith(root + \"/\")) {").contains(oldCheck));`. Optionally also require `return 2;` within a few lines after each call.

### IN-02: `homeRedirected` compares the now canonical `out` with paths that are not canonical

**File:** `src/app/mac_check/main.cpp:1510-1518` (called with the value that `outputDirIsStrictlyInside` now returns)
**Issue:** `out` is now the symlink-resolved path from the guard. `homeRedirected(out)` compares `<out>/home` with the unresolved `HOME` and `CFFIXED_USER_HOME` strings from the shell. It also tests `isBelow(..., root)` with `root = cleanPath(MAC_CHECK_ROOT)`, which is not resolved. If the checkout path, or `build/` itself, contains a symlink, `home_redirected` reports "no" and the `dialogs`, `panels` and `identity` sections refuse to run, although the guard accepted the directory. The failure is safe, since it refuses, but the message points at the environment variables and not at the symlink. `shown(path, out)` can likewise miss paths that Qt reports unresolved. Not reachable with a plain checkout directory.
**Fix:** Resolve `HOME`, `CFFIXED_USER_HOME` and `root` with `QFileInfo(...).canonicalFilePath()` before comparing, or compare `QDir(...).canonicalPath()` of both sides.

### IN-03: `exceedsOwnFile` duplicates `exceeds`

**File:** `src/core/ImageSizeLimit.cpp:12-30`
**Issue:** The two functions have the same body and differ only in the constants, and `exceeds(size, kind)` was added on top of them. A later change to one body (for example the treatment of a zero side) can drift from the other.
**Fix:** Add one private helper `exceedsLimits(const QSize&, int maxSide, qint64 maxPixels)` and let both public functions call it.

### IN-04: The page-cache test cannot fail against the current container

**File:** `src/pipeline_tests/TestBookSpread.cpp:423-436` (container at line 103)
**Issue:** `spreadPage()` stores its pages in a `std::map`, whose nodes never move, so `test_spread_page_cache_keeps_references` passes by construction. It only fails if someone replaces the map with a reallocating container. The rewrite makes it deterministic for that case: more than 16 insertions force a `std::vector` to reallocate. The cost is up to 17 extra spread pages, generated and cached for the rest of the run, also under the Debug and ASan builds. No record in the diff shows that the test was seen to fail against a `std::vector` cache. The new comment says "a container that reallocates when it grows must move the first page inside this case", which is true, but the guard is only as good as that mutation check.
**Fix:** Record in the test comment (or the phase record) that the test was run once against a `std::vector` cache and failed. If the extra renders cost more than the guard is worth, test a local cache of the same container type in a throwaway case instead of growing the shared one.
