# Include prune record, Phase 06.1 plan 08

Closes the Phase 6 review finding IN-01 (the split translation units of `OutputGenerator` and `MainWindow` repeated the include list of the file they were split from).

## Rule

A scratch script (`build/scratch/prune/prune.py`, not committed) went through the `#include` lines of one file in file order. It never removed these:

- the file's own header (`OutputGenerator.h` for the output files, `MainWindow.h` for the MainWindow files, or the header whose base name equals the file's own base name),
- `config.h` and `version.h` (`MainWindow.cpp` needs `config.h` for the `ENABLE_DEBUG_FEATURES` block, which only the Debug build defines),
- standard library headers (angle brackets, no dot in the name, not starting with `Q`),
- every header whose base name (file name without directory and extension, for example `QSize`, `Settings`, `bind`) occurs as a whole word in the file outside the include lines.

For every other include (the candidates) it removed the line and ran a syntax-only compile (`-fsyntax-only`, command taken from the compile database of the Release and of the Debug preset). It kept the removal only if every compile exited 0 and printed the same warnings as the compile before the pruning; otherwise it restored the line. For the two headers it compiled, in both presets, a scratch translation unit that includes only the header and every `.cpp` that includes the header, so a header still compiles on its own. Order: `OutputGeneratorProcessor.h`, then `OutputGeneratorPixelOps.h`, then the four `OutputGenerator*.cpp` files, then (second commit) the five `MainWindow*.cpp` files. Afterwards every file was formatted with `xcrun clang-format -i`.
