### WR-01: The own-file ceiling is below what the application can legitimately write, so the "every own file loads" guarantee does not hold

**Files modified:** `src/core/ImageSizeLimit.h`, `src/core/ImageLoader.h`
**Commit:** 087a386b
**Applied fix:** The reviewer's "Minimum" option, applied by orchestrator decision: comment-only, no constant and no executable code changed. The "Preferred" option (a write-side bound or refusal) was rejected because the project rule is that output for existing settings must not change, and a write-side refusal would block outputs the application writes today.

- `ImageSizeLimit.h`, doc comment of `kMaxOwnFilePixels`: removed the claim that every file the application wrote itself must load. The comment now says that the intended outputs are book and document scans at up to 1200 dpi, that the output dpi is not bounded by 1200 (the Change DPI dialog accepts up to 9999, `QIntValidator(0, 9999)` in `ChangeDpiDialog.cpp`, lines 57 and 74, checked), and that no write-side check exists. An output above the ceiling (a bilevel A3 page above about 2360 dpi, 28063 x 39685 px at 2400 dpi) or with a side above `kMaxOwnFileSide` is written, then refused on load and regenerated on every visit. This is accepted because such dpi values are outside the use of this fork. The reasoning about the constant, the forged header and the 4 GiB allocation is kept.
- `ImageLoader.h`, doc comment of `loadOwnFile`: replaced "far above anything the application writes, so a refusal only happens for a forged file" by "far above the outputs of ordinary settings. A refusal happens for a forged file or for an output above the ceiling (a very high output dpi), and makes the page regenerate."
- Two figures differ from the review text. The review gave "above about 2300 dpi" and 28063 x 39690 px; recomputed for 297 x 420 mm, the threshold is about 2357 dpi and 2400 dpi gives 28063 x 39685 px, so the comment says "about 2360 dpi" and 39685.
- `src/core/filters/output/Task.cpp` (lines 258-296) has no comment that repeats the guarantee, so it was not changed. A grep of `src/` for "must load", "far above anything" and "application wrote" found no other repeat in a code comment. `.planning/` files were left alone.

**Verification:** Tier 1 (re-read diff, comment-only, surrounding code intact). `xcrun clang-format --dry-run -Werror` on both headers printed nothing; no line exceeds 120 columns. No build and no ctest run, as instructed (the orchestrator runs them). The fix ran in an isolated worktree (`.claude/worktrees/`), fast-forwarded onto `gsd/phase-01-deletion-free-macos-build`, then removed.

### IN-02: `homeRedirected` compares the now canonical `out` with paths that are not canonical

**Files modified:** `src/app/mac_check/main.cpp`
**Commit:** aef5f009
**Applied fix:** Added a file-local `resolvedPath()` that cleans the path and resolves symlinks with `QFileInfo::canonicalFilePath()`. For a path that does not exist (the call returns an empty string) it resolves the deepest existing ancestor and appends the cleaned missing tail, and for a path with nothing resolvable it falls back to the cleaned path. An empty path stays empty. Added `samePath(a, b)` (false when the first side resolves to empty, so an empty or unset `HOME` or `CFFIXED_USER_HOME` gives "not redirected", never a match). `isBelow()` now resolves both the path and the root, and also refuses an empty root. `homeRedirected()` and the identity section compare `HOME`, `CFFIXED_USER_HOME` and `QDir::homePath()` with `<out>/home` through `samePath()`. `MAC_CHECK_ROOT` is resolved inside `isBelow()`. Added `#include <QFileInfo>`.

`isBelow()` is also used for `obs->underOut` in the panels section and for `settingsBelowHome` in the identity section; both now compare resolved paths too, which is consistent with the guard's resolved `out`. `shown(path, out)` was left unchanged: it replaces text inside a string, so the one-line treatment does not clearly apply, and the review marks a missed replacement there as cosmetic (a path printed unreplaced).

**Verification:** `xcrun clang-format --dry-run -Werror` printed nothing. Release build succeeded (only the existing `-Wunused-parameter` warnings from `InteractionHandler.h`). `ctest --preset macos-release -R qt_tests` passed (1 of 1). **No live harness run was done**: `mac_check` and `retina_check` were not run or launched, because they move the pointer and take focus. The new path code is therefore compiled and linked but not exercised in a real symlinked checkout.
