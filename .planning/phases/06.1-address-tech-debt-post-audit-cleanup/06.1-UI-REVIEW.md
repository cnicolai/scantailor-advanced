## Top 3 Priority Fixes

1. **Thumbnail tooltips no longer tell the two controls apart** — a user reading `Quality:` and `Size:` cannot tell from the tooltips which one changes the on-screen size of the thumbnail and which one changes its pixel resolution, and the default value is gone from both — **Fix:** rewrite the two strings in `src/app/SettingsDialog.ui` so each names one effect, for example `Quality:` → "The pixel resolution of each thumbnail image; a higher value gives a sharper preview and uses more memory." and `Size:` → "The on-screen size of each thumbnail in the page list." Keep each as a single-line translatable `<string>` (D-00d). The default value may be restored if the user wants it, because the drift risk that motivated removing it is about the Retina wording, not the default itself.

2. **An empty batch now stops silently** — the user presses start with nothing to process and the window simply returns to its main area with no message, so the press looks like it did nothing — **User impact:** the start action appears broken; before the fix this path crashed (SIGSEGV at address 0x28, per 06.1-07) — **Fix:** after `stopBatchProcessing()` in the `else` branch of `MainWindow::startBatchProcessing()` (`src/app/MainWindowBatch.cpp`, around line 116), show a short status-bar message such as "No pages to process." using `tr()`. This is a visible addition, so it needs a deliberate decision and is recorded as a deferred item rather than a silent change.

3. **No visual evidence exists for any change in this phase** — the Settings dialog tooltips, the empty-batch return and the path-button paint path were verified only by unit tests, source scans and gate runs, not by looking at the UI — **User impact:** a layout or text regression in the Settings dialog would go unnoticed — **Fix:** on the target Mac, open Settings → Thumbnails and hover both spin boxes to read the new tooltips, and start a batch on a project whose pages were all removed to confirm the main area returns cleanly. This is a manual check for the user to run; no live harness was started here.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- `src/app/SettingsDialog.ui:94` — tooltip for `thumbnailQualitySB` reads: "The pixel size of the thumbnail image. On a Retina display the image is built at this size multiplied by the display's pixel ratio." The Retina clause is kept; the default value and the display-model sentence are removed. The sentence still uses "pixel size" for a control named "Quality", which is ambiguous next to the Size control.
- `src/app/SettingsDialog.ui:137` — tooltip for `thumbnailSizeSB` reads: "The thumbnail size in the view." This names no unit, no range and no effect. It is less informative than before the phase (the default value was removed).
- Net effect: both tooltips are now shorter and less specific. Neither states the unit or the effect on the user's view. This is a copy regression in scope, not a regression of a declared contract (no UI-SPEC exists).
- Empty-state and error copy: no new strings were added. The `tr()` wrapping is preserved in the `.ui` file (`<string>` elements).
- `src/app/MainWindowBatch.cpp` (empty-batch return): no user-facing text is added on this path (see Pillar 6).

### Pillar 2: Visuals (3/4)

- No visual hierarchy, icon or focal-point change is present in the audited diff. Score is held at 3 because none of the in-scope surfaces was rendered for this review (code-only audit).
- `src/app/RelinkablePathVisualization.cpp` (`setPath`): the `//host` branch removed. On macOS, `RelinkablePath::normalize` already collapses a leading `//` or `\\` to one `/` (pinned by `src/core/tests/TestRelinkablePath.cpp`), so the branch was unreachable and the drawn path components are unchanged.
- `src/app/RelinkablePathVisualization.cpp` (`ComponentButton::paintEvent`): the `State_Enabled` line is kept; only the comment changed. No paint change.
- `src/app/MainWindow.cpp`: `changeEvent` removed. Visual impact is nil because no `QTranslator` is installed anywhere in `src/` at `HEAD` (translations were removed in Phase 3), so `QEvent::LanguageChange` is never sent at runtime.

### Pillar 3: Color (4/4)

- No colour, palette or colour-scheme code was changed in scope. `src/core/ColorScheme*` and the light and dark stylesheets are not in the diff.
- No new hardcoded hex or `rgb(` literal was introduced in the audited files.

### Pillar 4: Typography (4/4)

- No font family, size, weight or label text was changed. The only `.ui` changes are two `<string>` values inside `toolTip` properties, which render in the tooltip font only.

### Pillar 5: Spacing (4/4)

- No layout, margin, spacing or size property was changed in `SettingsDialog.ui` (the diff is 2 insertions and 2 deletions, both inside `<string>` elements).
- No `QLayout` or `setContentsMargins` change in the audited files.

### Pillar 6: Experience Design (3/4)

- **Empty batch (`src/app/MainWindowBatch.cpp`, `startBatchProcessing()`, around line 116):** the `else` branch now calls `stopBatchProcessing()` and returns. Before the phase, control fell through and dereferenced a null queue (SIGSEGV at address 0x28, reproduced by the offscreen test `testEmptyBatchStopsCleanly`). The crash is fixed. The remaining gap is feedback: the user gets no message, so the start action looks inert (see Priority Fix 2).
- **Language-change handling:** `MainWindow::changeEvent` deleted. This removes dead code (no translator exists), so no state transition is lost. Recorded as neutral rather than a positive, because the handler could never run.
- **Tooltips:** removing the default value and the Studio Display sentence removes information the user could use to decide a value. Counted in Pillar 1; it also reduces discoverability in this pillar.
- **Zoom comment (`src/app/MainWindowActions.cpp:334-347`):** comment wording only. The behaviour difference from `ZoomHandler::zoom()` (no move to the ideal position at zoom 1.0) is stated in the comment and is unchanged in code, so no user-facing behaviour changes.
- **Test-only accessors and diagnostics wording** (`src/core/ImageViewBase.h`, `src/core/filters/output/PictureZoneEditor.h`, `src/core/StageListView.h`): comment wording only; no behaviour change.
