<domain>
## Phase Boundary

Close the open items of the v1.0 milestone audit (`.planning/v1.0-MILESTONE-AUDIT.md`, verdict `tech_debt`) that can be fixed **without changing output**: the six "worth a small cleanup" items, the stale bookkeeping, the Phase 1 build warnings, the info-level review findings of Phases 1 to 6 under the triage policy below, and one measurement (fp-contract). ## Implementation Decisions

### Carried forward (not re-asked)

- **D-00d:** UI is English only; `tr()` stays on user-visible strings.
- **D-00e:** The app is never launched against the user's real settings or home folder; harnesses keep their state under `build/`.
- **D-00f:** Backlog 999.1 to 999.8 and the open `WINDOWS.md` entries stay out: their fixes change output and each needs its own phase with a golden update.

### Info findings triage policy (discussed with the user)
- **D-01:** **Fix cheap, record the rest.** Every info finding whose fix is a pure cleanup with no behaviour or output change is fixed (examples: unused includes, the dead `QEvent::LanguageChange` handling in `MainWindow::changeEvent`, Windows comments, DLL leftovers and stale `.gitignore` rules, dead test waits and stale test comments, wrong arithmetic in test comments, the misleading header text in Phase 2 IN-01). Every finding whose fix would need a design decision, a live harness run, a manifest change or a behaviour change gets a one-line won't-fix or deferred reason in its phase's `*-REVIEW-DISPOSITION.md`. The planner re-reads each finding against the current tree first: several may already be moot after Phases 3 to 6 (for example Phase 1 IN-01's non-macOS CI, Phase 1 IN-02's `PORTABLE_VERSION`), and those are closed as `fixed by <phase/plan>` with the evidence.
- **D-02:** Findings whose fix would touch the golden manifest (Phase 3 IN-06, `qt_compile` meaning) are won't-fix or doc-only, because D-00a forbids manifest changes.
- **D-03:** A "dead" branch is removed only if it is provably unreachable on macOS. Phase 3 IN-03's UNC branch is checked for reachability with a `//`-prefixed path first; if it is reachable it stays and is pointed at backlog 999.8 (`RelinkablePath` backslash handling) instead.
- **D-04:** Phase 2 IN-02 / audit "coincidental reliance" (`test_spread_page_cache_keeps_references` detects a reallocating container only when run alone): fix it if the test can be made to fail deterministically under a normal run (e.g. by forcing the reallocation it guards against); otherwise record it as won't-fix with that reason.

### Planning references in source comments (discussed with the user)
- **D-05:** The bare planning references in comments under `src/` and in `CMakeLists.txt` files (`D-03`, `WR-01`, `IN-04`, `Phase 4`, `plan 05-01` and the like; 93 occurrences in 33 files at discussion time) are **rewritten as the plain reason they stand for**, in a few words, so each comment makes sense without `.planning/`. Example: "kept byte-for-byte (D-01)" becomes "kept byte-for-byte so output stays identical". A full repository path to a file that exists (for example a record under `.planning/.../records/`) may stay. Closing check: a grep for bare `\b(D-[0-9]{2}[a-z]?|WR-[0-9]{2}|IN-[0-9]{2}|Phase [0-9]|plan 0[0-9]-[0-9]+)\b` under `src/` and in the CMake files returns nothing except the allowed paths. Closes Phase 1 IN-04 and Phase 4 IN-04. Comment-only edits; `__LINE__` shifts in assert messages are acceptable, goldens are the proof.

### Phase 1 build warnings (discussed with the user)
- **D-06:** **WR-03:** `SANITIZE` (`CMakeLists.txt:45-51`) accepts only a known list of sanitizer names (at least `address`, `undefined`, `thread`, comma-separated) and fails at configure time otherwise; the value reaches the compiler as list items, not as a pasted string. The default build (empty `SANITIZE`) must produce an empty build-command diff. Phase 3 WR-02 (orphaned comment in this Clang flag block, kept byte-for-byte until the block is next touched) is fixed in the same commit, because this is that touch.
- **D-07:** **WR-04:** Boost is found through its own CMake config (`find_package(Boost CONFIG ...)`, `Boost::headers`, `Boost::unit_test_framework` targets) instead of the FindBoost-only `Boost_INCLUDE_DIRS` / `include_directories` (`CMakeLists.txt:85-100`). `BOOST_TEST_DYN_LINK` and `BOOST_MULTI_INDEX_DISABLE_SERIALIZATION` stay in effect. Proof: `otool -L` on every test binary shows the same Boost dylib as before, and the gate-log row explains the build-command diff line by line.

### Harness findings (discussed with the user)
- **D-08:** Fix the harness findings that can be verified offscreen: the lexical output-path guards (Phase 3 IN-04 `ui_snapshot`, Phase 4 IN-05 `retina_check`, Phase 5 IN-05 `mac_check`) become a canonical-path check that the target lies strictly inside `build/` (the build root itself refused); `ui_snapshot` rejects unknown options instead of taking them as the output directory (Phase 3 IN-05). Each guard is factored so a test can call it without starting the live harness. If a guard cannot be tested that way, it is recorded as won't-fix instead of shipping an unverified change.
- **D-09:** Won't-fix with the reason "needs a live run; verdicts are correct on the one target machine": Phase 5 IN-02 (US-layout alias keys), IN-03 (German layout required), IN-04 (fixed 800 ms wait).

### Sanitizer gate (Claude's decision; user did not select the area)
- **D-10:** Phase 1 WR-01: `ctest --preset macos-asan` must fail when ASan or UBSan reports a finding (halt on error, or `FAIL_REGULAR_EXPRESSION` on `ERROR: AddressSanitizer|runtime error:`; research picks the mechanism that also catches findings in passing tests). Today's collect-everything behaviour moves to a separate `macos-asan-collect` test preset. The known UBSan reports (`.planning/phases/02-golden-baselines/records/sanitizer-findings.md`: `BinaryImage.cpp:1044` null `SharedData` member access; left shifts of negative values in `Despeckle.cpp:368/392/418/446` and `InfluenceMap.cpp:129/130`; negative shift exponent in `EstimateBackground.cpp:243`; plus anything a fresh run finds) are **fixed in code**, each with the goldens as proof (byte-identical in Release and Debug). A fix that moves any golden is reverted and that location gets a narrow UBSan suppression entry plus a backlog item instead. The strict preset must end green. The full ASan run takes about 11 minutes (pipeline_tests); run it after the UBSan fixes and once at the end, not per commit. — **Reversibility:** reversible — preset and environment only.

### Output-folder read limit (Claude's decision; user did not select the area)
- **D-11:** Phase 6 IN-05: the application's own files (output cache, foreground/background/original-background layers, automask, speckles) get a **fixed own-file ceiling**, higher than the source limit in `src/core/ImageSizeLimit.h`, instead of no limit. It is a constant, not a share of RAM, for the same reasons as Phase 6 D-01 (same result on every machine, testable with a forged header); the reviewer's `MemoryBudget` suggestion is not taken. Research derives the value from the largest output the app can legitimately write (largest accepted source size × highest output dpi factor) and records why, so a file the app wrote itself is never refused (a refusal would regenerate the page on every visit). A refused file yields a null image, which takes the existing `needReprocess` path in `src/core/filters/output/Task.cpp:258-296`: the page is regenerated, no new message. Test: a tiny TIFF with a forged huge header at the expected output file name makes the page reprocess without a large allocation (checked under the strict ASan preset or by timing). — **Reversibility:** reversible — one constant.
- **D-12:** Phase 6 IN-04: delete the unused `ImageLoader::load(const ImageId&)` overload (`src/core/ImageLoader.h:22`, `ImageLoader.cpp:20-22`).

### fp-contract measurement (Claude's decision; user did not select the area)
- **D-13:** Phase 1 WR-02 / BUILD-07 residual: a **one-off measurement, no default change**. Build the current tree in a scratch build directory under `build/` with `-ffp-contract=on` (the Apple Clang default) instead of `off`, run `pipeline_tests` in compare-only mode against the committed goldens, and record per golden whether it is byte-identical or how much it differs (pixel count and maximum difference) in a record file in this phase directory. `UPDATE_GOLDENS` stays unset; no golden is rewritten. The comment at `CMakeLists.txt:42` is narrowed to say the freeze applies to Clang. The result is information for the user; a decision to change the flag would be a separate phase.

### Straightforward fixes (Claude's decision)
- **D-14:** Phase 6 IN-06: `startBatchProcessing()` returns right after `stopBatchProcessing()` when the sequence yields no task (`src/app/MainWindowBatch.cpp`, the `else` branch), with an offscreen test for a project without pages if one can be set up cheaply.
- **D-15:** Stale OpenGL lines in `.claude/CLAUDE.md` (Qt `OpenGL`/`OpenGLWidgets` in the Frameworks and Key Dependencies lists, the deleted `src/core/OpenGLSupport.cpp`) are removed, and `TestMacQt::testNoOpenGlInSourcesOrBuild` (`src/qt_tests/tst_mac_qt.cpp:1728`) also scans `.claude/CLAUDE.md` so the drift cannot return.
- **D-16:** Bookkeeping: `.planning/phases/01-deletion-free-macos-build/deferred-items.md` marks ScaleTestSuite/test_random_image fixed by plan 02-04; `02-UAT.md` status becomes resolved (gap closure G-02-3, re-verification passed); Phase 3 WR-01 disposition becomes `fixed` by the `app_gui` library (plan 05-01; `src/app/CMakeLists.txt:53-56`) — the audit listed it as open from the stale disposition; the stale "open" notes in `PROJECT.md` Context and `STATE.md` Blockers are corrected; `STATE.md` "Current focus" is updated at the phase transition.

### Claude's Discretion
- Whether to rename the remaining unlimited `ImageLoader::load` overloads to a name that carries the trust decision (e.g. `loadOwnFile`), as Phase 6 IN-04 suggests. Do it if the call sites are few and the rename is mechanical.
- Phase 4 IN-01 (test-only accessors in production classes): grouping them under one diagnostics comment counts as the cheap fix; moving them behind a friend accessor is not required.
- Phase 4 IN-02 (Settings tooltip hard-codes a display model and a default) and Phase 4 IN-03 (ctest sets `QT_QPA_PLATFORM=offscreen`, which `main()` overrides): fix if the change is local; otherwise record.

- Plan breakdown and order. Suggested: bookkeeping and docs first, then D-05 comment rewrite (large but mechanical), then code fixes, then build-file changes (D-06, D-07, D-10), then the D-13 measurement and the closing strict-ASan run.
