- Qt's Cocoa key mapper matches Option chords through `QAppleKeyMapper::possibleKeyCombinations`, which uses the event's native virtual key and the current layout; `QTest::keyClick` bypasses it, so only NSEvent-level input answers the German-layout question (RESEARCH "Live harness" note).

The record says so (RESEARCH Pitfall 10).

## Reconciliations

- CONTEXT discretion allows the Info.plist only "if it shows the bare process name". The harness cannot measure the app binary itself (convention 3); it measures its own process, which follows the same CFBundleName rule. The plist is therefore linked into both `scantailor-advanced` and `mac_check`, so the harness shows exactly what the app shows, and the app binary's section is checked separately by extracting it.
- CONTEXT discretion makes the plist conditional on "settings and profile paths stay unchanged". A path computed after the harness's own `setPath` cannot change, so the section `identity` repeats the app's order instead (facts above): it runs in its own launch with `HOME` and `CFFIXED_USER_HOME` redirected to `<output-dir>/home`, so the default-constructed `QSettings` reads below `build/` and never the user's file. `bundle_name` proves the measured process carries the plist, and the names and paths it records would differ if the plist reached them.
- UI-SPEC keeps Help in the `.ui`; RESEARCH Pitfall 3 says an empty Help may show. The harness decides; if it shows, About moves into File (UI-SPEC's pass criterion "About only in the application menu" still holds).
