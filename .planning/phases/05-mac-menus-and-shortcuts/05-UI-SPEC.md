# Phase 5 — UI Design Contract

> Interaction and copy contract for the Mac menus and shortcuts phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker. This is a native Qt 6 Widgets desktop app, so the web-oriented template sections are mapped to what this phase touches. Visual tokens are unchanged. The substance is the menu bar, the key bindings, the key names in text, the context-menu triggers, the batch-finished sound and the native file panels.

Sources: `05-CONTEXT.md` (D-00a to D-12 and Claude's Discretion), REQUIREMENTS MAC-01 to MAC-11, FEATURES Area 3, PITFALLS 9, 10 and 18, and the source files named in CONTEXT code_context. Where CONTEXT left a choice to Claude, the row says **Claude's choice** and gives a one-line reason. No question is left open for the user (decision gates are delegated).

## Spacing Scale

**Unchanged, existing Qt layouts and QSS.** This phase introduces no spacing token, margin or padding value and changes no `.ui` geometry except adding the View menu to the menu bar. Menu item spacing is drawn by macOS (native menu bar) and Qt (context menus); neither is configured here.

Exceptions: none.

## Typography

**Unchanged, existing application font and QSS.** No size, weight or line-height is declared or changed. Menu bar and application menu text are rendered by macOS in the system menu font.

Text-content rules that do apply (they are copy, not typography):

- Modifier and key symbols are plain Unicode characters in the string, in the same font as the surrounding text: ⌘ (U+2318), ⌥ (U+2325), ⇧ (U+21E7), ⌃ (U+2303), ⌫ (U+232B), ⌦ (U+2326), the ellipsis … (U+2026).
- In the rich-text help (`page_layout/OptionsWidget.ui`) the existing bold spans and 7pt size are kept as they are; only the key text inside them changes.

---

## Color

**Unchanged, existing light and dark colour schemes.** No colour, accent or destructive colour is introduced. The native menu bar and the macOS application menu follow the system, not the scheme. No 60/30/10 split is declared because no surface is added.

Accent reserved for: not applicable (no new coloured element).

Destructive actions (remove zone, Remove Content Box) use no colour: their context-menu items keep the default menu text colour, as today.

## Interaction Contract

### 1. Menu bar structure (MAC-01, MAC-02, MAC-03, MAC-05, MAC-09)

Left to right on screen. The first entry is the macOS application menu, built by Qt from the `menuRole` actions; it is not a `QMenu` in `MainWindow.ui`.

| Menu | Items, top to bottom | Notes |
|------|---------------------|-------|
| **Application menu** (bold, system) | About ScanTailor Advanced; separator; **Settings…** ⌘,; separator; (system items: Hide, Hide Others, Show All); separator; **Quit** ⌘Q | Built by roles: `actionAbout` = `AboutRole`, `actionSettings` = `PreferencesRole`, `actionQuit` = `QuitRole`. The Settings item reads "Settings…" because macOS names it. Roles are set before the window is first shown. |
| **File** | New Project… ⌘N; Open Project… ⌘O; separator; Save Project ⌘S; Save Project As… ⇧⌘S; separator; Close Project ⌘W | `actionQuit` stays declared in File in `MainWindow.ui` (the role moves it). File must not be left with an orphan separator after hoisting. |
| **View** (new, between File and Tools) | Fix Orientation ⌘1; Split Pages ⌘2; Deskew ⌘3; Select Content ⌘4; Margins ⌘5; Output ⌘6; separator; Zoom In ⌘+; Zoom Out ⌘-; separator; Larger Thumbnails ⌥⌘+; Smaller Thumbnails ⌥⌘- | D-04, D-08. Stage names are exactly the `Filter::getName()` strings. |
| **Tools** (`menuDebug`, title unchanged) | Fix DPI…; Relinking…; Reverse Two-Page Spread Order; separator; Default Parameters…; Units ▸ (Pixels, Millimetres, Centimetres, Inches); separator; Debug Mode | **Settings is removed** (MAC-01). Debug Mode and the separator before it are hidden together when `DEVELOPER_VERSION` is off, so Tools never ends on a separator. Object name `menuDebug` is not renamed (no gain, avoids churn). |
| **Help** | (empty after About moves to the application menu) | **Claude's choice:** leave the menu in the `.ui`, accept that Qt and macOS show no Help menu while it is empty; reason: the only entry belongs in the application menu (MAC-01), and a cheat-sheet is deferred (CONTEXT deferred, FEATURES MAC-26). The harness records what the bar actually shows. |

Menu text rules (**Claude's choice**, Apple style):

- Title Case for menu items ("Reverse Two-Page Spread Order", not "Reverse two-page spread order"). Reason: Apple HIG and the menu bar of every other Mac app.
- A command that opens a dialog ends in the single character … with no space before it ("Open Project…", "Fix DPI…", "Default Parameters…"). The old " ..." (space plus three dots) is replaced in menu actions only. Tooltips keep their text apart from the key names listed in section 5.
- No `&` mnemonics, no "Exit" wording.
- Shortcuts are never typed into the menu text; they come from `QAction::setShortcut(s)` so macOS draws them (⌘N, ⇧⌘S).

`menuRole` assignment (**Claude's choice**: every action that is a direct child of File, View, Tools or Help gets an explicit role, so no heuristic runs):

| Action | Role |
|--------|------|
| `actionAbout` | `AboutRole` |
| `actionSettings` | `PreferencesRole` (shortcut `QKeySequence::Preferences`, ⌘,) |
| `actionQuit` | `QuitRole`, still connected to `close()` so `closeEvent` shows the unsaved-changes prompt for ⌘Q, the application menu and the Dock |
| every other direct child (`actionNewProject`, `actionOpenProject`, `actionSaveProject`, `actionSaveProjectAs`, `actionCloseProject`, `actionFixDpi`, `actionRelinking`, `actionReverseTwoPageOrder`, `actionDefaults`, `actionDebug`, the six stage actions, the four zoom/thumbnail actions) | `NoRole` |

Reason for NoRole everywhere: "Default Parameters…" and any future text containing "settings", "options", "about" or "quit" would otherwise be hoisted by the heuristic (PITFALLS 10). Actions inside the Units submenu are not direct children of a top-level menu, so roles do not apply to them.

Application menu name (CONTEXT Discretion, outcome contract): the bold menu title and "About …" should read **ScanTailor Advanced**. Research measures what Qt 6.12 shows without a bundle. If it shows the bare process name `scantailor-advanced`, embed a minimal Info.plist section (`-sectcreate __TEXT __info_plist`, `CFBundleName` = "ScanTailor Advanced") and prove with the harness that the settings file path and the profiles path are byte-identical afterwards (they depend only on `Application::setApplicationName` / `setOrganizationName` in `main.cpp`, which are not changed). If the plist does not change the title, accept the process name and record it. No `.app` bundle (POLISH-05 stays deferred).

Menu bar while a dialog is open (MAC-09, **Claude's choice** by measurement, in this order):

1. First measure with the live harness. If the bar keeps the application menu plus File, View and Tools titles while Settings, Fix DPI, Relinking, Default Parameters, About and a native file panel are open (items may be greyed), add nothing.
2. If the bar is empty or reduced to the system items, create one parentless `QMenuBar` before the first dialog opens (Qt: the first parentless bar becomes the default). It holds the same `QAction` objects (not copies) in two menus: File containing `actionQuit`, and Help containing `actionAbout`. Same objects keep one `closeEvent` path for Quit and avoid a second action set.
3. Pass criterion either way: the application menu is present and the bar is not empty while any dialog is open; About and Quit are not duplicated in the application menu.

### 2. Shortcut map (D-01 to D-10, MAC-02 to MAC-05, MAC-07)

"Window" means `Qt::WindowShortcut`, the default. Qt's `Ctrl` is ⌘ (D-00b); the key text below is what the user presses.

| Command | Binding(s) | Where | Source |
|---------|-----------|-------|--------|
| New Project | ⌘N | window, File menu | existing, kept |
| Open Project | ⌘O | window, File menu | existing, kept |
| Save Project | ⌘S | window, File menu | existing, kept |
| Save Project As | ⇧⌘S (`QKeySequence::SaveAs`) | window, File menu | MAC-03; flow not restructured (CLEAN-05 is Phase 6) |
| Close Project | ⌘W | window, File menu | existing, kept |
| Quit | ⌘Q (`QKeySequence::Quit`) | window, application menu | existing, role added |
| Settings | ⌘, (`QKeySequence::Preferences`) | window, application menu | MAC-02 |
| Go To Page | ⌘G | window, toolbar button tooltip | existing, kept (not in a menu) |
| Switch stage 1 to 6 | ⌘1 to ⌘6 **and** O, E, N, V, K, P | window, View menu shows ⌘1 to ⌘6 | D-01, D-03. Primary shortcut ⌘n first, letter second, in one `setShortcuts` list so the menu shows ⌘n. |
| Output tab 1 to 5 | ⌥⌘1 to ⌥⌘5 | Output stage page view only | D-02; was ⌘1 to ⌘5 |
| Zoom In (page view) | ⌘+ and ⌘= | window, View menu shows ⌘+ | D-06 (German layout: ⌘+ is the key pressed; ⌘= for US) |
| Zoom Out (page view) | ⌘- | window, View menu | D-06 |
| Zoom In / Out, plain keys | + and - | page view | D-06, existing in `ZoomHandler`, kept |
| Larger Thumbnails | ⌥⌘+ , ⌥⌘= | window, View menu shows ⌥⌘+ | D-07; was ⌘+ |
| Smaller Thumbnails | ⌥⌘- | window, View menu | D-07; was ⌘- |
| Create Content Box | **B**, Ins | Select Content page view, context menu | D-09 |
| Remove Content Box | **⌫** (`Key_Backspace`), **⌦** (`Key_Delete`) | Select Content page view, context menu | D-10 |
| Remove zone under the pointer | **⌫**, **⌦** | zone editors (Output stage picture and fill zones) | D-10; was `Key_Delete` only |
| Remove vertex under the pointer | D | zone editors | existing, kept |
| Zone mode | Z, X, C | zone editors | existing, kept |
| Page navigation | PgUp/Q, PgDown/W, Home, End, ⇧ variants, F5 reload | window | existing, kept untouched |

Binding rules:

- Multiple bindings per action use `setShortcuts({...})`, never `setShortcut` twice (the second call replaces the first). The first entry in the list is the one drawn in the menu or context menu; the order above is the order in the code (Mac key first: ⌘n, then ⌘+, then ⌫, then B).
- Ins is a hidden second binding for Create Content Box: the context menu shows B, and Ins appears in no menu, tooltip, status tip or help text (so the MAC-06 string check and this table agree).
- The View-menu zoom actions drive the page view's existing `ZoomHandler::zoom()` step, 2^(±1/6), with the same focus rule as the plain keys (cursor if it is over the view, else the view centre). They are disabled when no page view is shown. They never act on the thumbnail strip.
- ⌫ and ⌦ stay **"under the pointer"** with no undo and no confirmation, as today. With no zone or box under the pointer the key does nothing (no beep, no dialog).
- ⌫, ⌦, B, D, Z, X, C, +, - and the single stage letters are window-context shortcuts. They must **not** fire while a text, spin-box or combo-box field in the options panel has focus (those widgets accept `ShortcutOverride`; the permanent test proves it for a spin box and a line edit, PITFALLS 9).
- Output stage tabs (⌥⌘1 to ⌥⌘5) and stage switching (⌘1 to ⌘6) never share a key. ⌘1 in the Output stage switches to stage 1, not to tab 1.
- No binding uses plain ⌘H, ⌘M, ⌘Space or ⌘Tab (reserved by macOS).
- `Qt::AA_MacDontSwapCtrlAndMeta`, a `Meta` primary modifier and a parallel Ctrl set stay excluded (D-00b). Existing `ControlModifier` / `AltModifier` gesture code is not edited.

⌥⌘ on the German layout (D-12 harness proof, **Claude's choice of fallback**): Option changes the character a key produces (⌥1 gives ¡, ⌥+ gives ±). The harness must show ⌥⌘1 to ⌥⌘5, ⌥⌘+ and ⌥⌘- firing on the German layout. If one does not fire, switch that group to ⌃⌘ (`Qt::META | Qt::CTRL`, ⌃⌘1 to ⌃⌘5, ⌃⌘+, ⌃⌘-) and update the menu, tooltips and tests for the group together. Reason: ⌃⌘ is the nearest chord that does not change the typed character and is not used by the app. Record the outcome in `records/` and tell the user.

### 3. Context menus (MAC-08)

| Trigger | Result |
|---------|--------|
| Right-click (secondary button) | zone context menu / content-box menu / guide menu opens |
| Two-finger click (system secondary click) | same, delivered as a right-click by macOS |
| ⌃-click (physical Control) | same, delivered as a context-menu event by Qt/Cocoa |

- All three must reach the existing `contextMenuEvent` handlers (`ImageViewBase`, `output/ImageView`). No `Qt::RightButton` special-casing is added.
- Choosing an item works on the first click.
- The 200 ms `Q_OS_MAC` deferral in `ZoneContextMenuInteraction::menuAboutToHide` (**Claude's choice: keep**) stays unless the harness measures, over repeated runs on Qt 6.12 and current macOS, that `triggered()` always arrives before `aboutToHide()` returns; then it is removed with a test. Reason: keeping it costs only a 200 ms wait after dismissing a menu, while dropping it wrongly would cancel valid menu choices.
- Because ⌃-click is the system right-click, ⌃ is never required for any gesture. Gestures use ⌘, ⌥ and ⇧ only.

### 4. Batch-finished alert (MAC-10)

When the last page of a batch run is processed and "Beep when finished" is checked: call `QApplication::beep()` exactly once (the system alert sound). `QApplication::alert(this)` still runs (Dock attention). No shell, no `std::system`, no `QProcess`, no `play`/`afplay`. A stored `main_window/external_alarm_cmd` is ignored and left in the settings file (D-00d). The checkbox label "Beep when finished" and its default are unchanged.

### 5. File panels (MAC-11)

Every `QFileDialog` is the native NSOpenPanel / NSSavePanel. No `DontUseNativeDialog` anywhere in `src/`. In `RelinkingDialog.cpp` both calls (substitution file and substitution directory) drop the option and keep their titles, start directories and result handling; the explanatory code comment about non-native dialogs is removed. The native folder panel shows files greyed out, which is acceptable for choosing a replacement directory; relinking must still accept a file or a folder that exists. Panel titles and button labels are provided by macOS.

## Copywriting Contract

### Key-name style (MAC-06, Apple style)

| Rule | Example |
|------|---------|
| Modifier order is ⌃ ⌥ ⇧ ⌘ (Apple order) | ⇧⌘S, ⌥⌘1 |
| Shortcuts: symbols run together with the key, no `+` between them | ⌘G, ⇧⌘S, ⌥⌘+ (the last `+` is the Plus key) |
| Mouse gestures: symbols, a hyphen, then the lower-case gesture | ⌘-click, ⇧-click, ⇧⌘-click, ⌥⌘-click, ⌘-wheel, ⇧⌘-wheel, ⌥-wheel |
| Holding a modifier alone | "Hold ⌘", "Hold ⇧ or ⌘" |
| Delete keys | ⌫ for the Mac Delete key (Backspace), ⌦ for forward delete. Text says "Press ⌫". |
| ⌃ is written only where the physical Control key is meant | "⌃-click" is allowed in help only; no gesture in this phase requires it |
| Words "Ctrl", "Alt", "Control", "Option", "Cmd", "Del", "Ins" never appear in user-visible text | enforced by the ctest string check (D-12) |
| Plain keys keep their names | Home, End, PgUp, PgDown, Q, W, B, Z, X, C, D, F5 |

Strings built from a real `QKeySequence` at run time use `toString(QKeySequence::NativeText)`. A small helper for modifier names is acceptable but not required: **Claude's choice: literal symbols in the `tr()` source strings and `.ui` text**, because none of these strings is built from a sequence and the target is one Mac. Reason: simplest, greppable, one source of truth per string.
