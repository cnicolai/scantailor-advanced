## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings file → shell | `main_window/external_alarm_cmd` from the INI is passed to `std::system` when a batch finishes with "Beep when finished" on |

| Diagnostics → records | stderr and crash reports can hold paths and user data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-14 | Elevation of privilege | `std::system` alarm at `src/app/MainWindow.cpp:1337` | medium | accept | Observed only in Phase 1 (D-06); the value comes from the user's own INI, so an attacker who can write it already runs code as the user (not a primary trust boundary); Phase 5 (MAC-10) replaces it with the system beep; prior settings were listed or moved aside in plan 01-05 |
| T-01-15 | Tampering | launch fixes | high | mitigate | D-07 rule: platform/toolchain causes only, smallest change, own commit with reason, fix-log row, stop and ask before any change to processing arithmetic or output; plan 01-07 audits the diff |
| T-01-16 | Information disclosure | `smoke-stderr.txt`, crash reports | medium | mitigate | stderr normalised (`{repo}`, `~`, `{scratch}`) before commit, verify counts `$HOME` occurrences; crash reports under `~/Library/Logs` read only after the user's yes |
| T-01-SC | Tampering | package installs | high | mitigate | This plan installs nothing; any install would have to pass the plan 01-01 homebrew/core gate |
