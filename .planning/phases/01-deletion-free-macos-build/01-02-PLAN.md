## Fix rules for this plan (D-07, research Pitfalls 5 and 7, research PITFALLS.md Pitfall 12)

- Smallest change that compiles. Expected classes: missing transitive includes under libc++ (`<cstdint>`, `<algorithm>`, `<memory>`, `<limits>`, `<cstring>`, `<cmath>`), `size_t` versus `uint64_t` overload mismatches, Qt 6.12 API removals in Qt 6 arms, Boost 1.92 header changes, `-Werror=return-type` errors.
- A fix in processing code (`src/imageproc/`, `src/math/`, `src/dewarping/`, `src/core/filters/`) is allowed without asking only when it is provably value-identical: an include, a declaration, a type spelling, or a cast between types that hold the same values on this platform. Write in the fix-log row why it is identical.
- STOP and ask the user (return a `checkpoint:decision`) before any edit that changes an expression evaluated during image processing, any edit to `src/dewarping/DetectVertContentBounds.cpp` or `src/dewarping/DistortionModelBuilder.cpp` (their Qt-version arms wrap RANSAC/dewarp code, research Pitfall 5), and any `-Werror=return-type` error inside processing code. For the return-type case, offer: (a) add the return the code path implies, with its effect on output stated; (b) demote `-Werror=return-type` to a plain warning for Phase 1 and record the site. Do not choose silently (research Pitfall 7).
- A `-Werror=return-type` error outside processing code (UI, project I/O) is undefined behaviour that Clang exposes, so D-07 allows the smallest fix in its own commit.
- Boost 1.92 breakage: prefer a documented Boost compatibility define added next to `add_definitions(-DBOOST_MULTI_INDEX_DISABLE_SERIALIZATION)` in `CMakeLists.txt` (a build setting), else a source fix under the rules above, else stop and ask. Never install another Boost (prohibition).
- Never delete a code path. Inside a `QT_VERSION` conditional, change only the Qt 6 arm. Never add `GL_SILENCE_DEPRECATION` or other warning-silencing defines (D-08).
</context>
