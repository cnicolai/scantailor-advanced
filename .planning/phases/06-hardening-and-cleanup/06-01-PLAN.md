## Conventions for every plan of this phase

Later plans refer to this section and repeat the items their tasks need.

1. Every command runs from the repository root; every path in a plan is relative to it.
2. Scratch files go to `build/scratch/` (gitignored), never `/tmp` or anywhere outside the project. Write files with the Write tool; never run a bare `cat > file` (it blocks on stdin). macOS bash 3.2 cannot parse a quoted heredoc inside `< <(...)`: put helper scripts in their own file. Python runs as `python3 -I`.
3. Nothing outside the project is opened, listed or written by you. Never touch `~/.config/scantailor-advanced/`, `~/Library/...`, OmniFocus or Google Chrome. Build tools and programs built from this checkout may read `/opt/homebrew` and the Xcode / Command Line Tools installation (`.planning/phases/02-golden-baselines/records/access-approval.md`); do not open files there yourself. Never launch `build/<preset>/scantailor-advanced` (D-00e): it reads and writes the user's settings. Tests keep settings and temporary files under `build/<preset>/test-tmp`.
4. Formatting: run `xcrun clang-format -i <file>` on every C++ file you touch and check with `xcrun clang-format --dry-run -Werror <file>`. Exception: `src/dewarping/TextLineTracer.cpp` keeps two older violations; never run `-i` on it, edit it with the Edit tool only, and check that `xcrun clang-format --dry-run src/dewarping/TextLineTracer.cpp 2>&1 | grep -c 'warning:'` still prints 2. `.ui`, CMake and Python files are not formatted.
5. Code style (`.claude/CLAUDE.md`): C++17 only; new files start with the two-line copyright header that every existing file carries (`// Copyright (C) 2019  Joseph Artsimovich ...` and the GPLv3 line); include guards `SCANTAILOR_<MODULE>_<NAME>_H_` in `src/` (check the module token of a neighbouring header), `TST_<NAME>_QT_H` in `src/qt_tests`; no `#pragma once`; `m_` prefix for members; `const` wherever possible; one parameter per line when a list wraps; module headers by bare name; no new `qDebug`/`qWarning` in application code; user-visible strings stay in `tr()` or `QCoreApplication::translate` (D-00d: English only, no translation files); no raw `new` except Qt objects handed to a parent or to an owning interface.
6. Tests and the code they cover land in the same commit. Every commit must pass the gate, so there is no failing-test commit and no RED/GREEN split.
7. Gate (D-00a). Every commit that changes a path outside `.planning/` and `.claude/` passes `bash .planning/phases/03-qt-6-and-macos-only/gate.sh check <label>` on that commit, run right after the commit and before any other commit. Commit first, then gate; when the gate fails, fix the cause, `git commit --amend`, and rerun with the same label until `result: PASS`. The gate configures, builds (all targets, including `mac_check`, `retina_check`, `ui_snapshot`) and runs Release and Debug ctest; it takes 5 to 10 minutes: start it with the Bash tool in the background (`run_in_background`), wait for its exit notification (do not poll), then read `build/scratch/gate/<label>/summary.txt`. Never set `UPDATE_GOLDENS`. The gate refuses to run with uncommitted changes under `src`, `CMakeLists.txt`, `CMakePresets.json`, `cmake`, `config.h.in` or `version.h.in`.
8. After a commit passes, append its row to `.planning/phases/06-hardening-and-cleanup/records/gate-log.md` and commit that file alone as `docs(06-NN): gate record for <label>`. Columns: `| Label | Commit | Subject | Release ctest | Debug ctest | Goldens | Command diff (release / debug) | Expected diff met |`. "Command diff" takes the `diff_lines` values of the summary; "Expected diff met" says what you found when you read `cmds-<preset>.diff` (edit-only commits: empty; commits that add or remove a source file or a library: only those compile, archive, link and automoc lines).
